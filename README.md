# Clarity 1.2.1 — 유튜브 GPU 영상 보정

RIFE v1.3 개발 중: [현재 진행·재개 방법](RIFE_PROGRESS.md). [720p·1080p 추가 FPS 검증](docs/rife/FPS-MATRIX-REPORT.ko.md)은 기존 Framegen 하네스를 재사용한 개발 경로이며, YouTube 제품 경로에는 아직 연결하지 않았습니다. 기존 설치 ZIP은 v1.2.1 보존본입니다. [윤곽선 떨림 진단과 미채택 후보](docs/rife/TEMPORAL-EDGE-REPORT.ko.md)도 기록했습니다.

실제 영상 프레임을 WebGPU 또는 WebGL2로 재구성하는 Manifest V3 확장 프로그램입니다. WebGPU에서는 양방향 블록 움직임 추정과 워핑으로 중간 프레임을 만듭니다. 유튜브의 디코딩·스트리밍·오디오·자막·컨트롤을 그대로 사용하며, 영상 파일을 업로드하지 않습니다.

[v1.2.1 병목 분석·성능 검증 보고서](docs/v1.2.1/REPORT.ko.md)에서 실제 측정값, 테스트 로그, 픽셀 증거와 한계를 확인할 수 있습니다. [v1.2 보고서](docs/v1.2/REPORT.ko.md)와 [v1.1 보고서](docs/review/REVIEW.ko.md)와 [v1.0 검증 기록](docs/VALIDATION.md)은 과거 기록입니다.

## 설치

1. Chrome의 chrome://extensions 또는 Edge의 edge://extensions 를 엽니다.
2. 개발자 모드를 켜고 **압축해제된 확장 프로그램을 로드합니다**를 선택합니다.
3. 프로젝트의 **dist 폴더**를 선택합니다. ZIP을 받았다면 압축 해제 후 manifest.json이 들어 있는 폴더를 선택합니다.
4. 확장 프로그램을 다시 로드한 뒤 **기존 유튜브 탭도 새로고침**합니다.
5. Clarity 팝업에서 실제 표시 상태와 처리 해상도를 확인합니다.

기본값은 보정·자동 성능 조절 켜짐, 목표 1080p, FPS 원본, 채도·밝기 100%입니다.

## 설정과 실제 동작

| 설정 | 동작 |
| --- | --- |
| 원본 해상도 | 재구성 확대 생략. 색상·지원되는 노이즈 보정 유지 |
| 720p | 원본 높이 480 이하에서 높이 720으로 확대 |
| 1080p | 원본 높이 720 이하에서 높이 1080으로 확대 |
| 1440p | 원본 높이 1080 이하에서 높이 1440으로 확대 |
| 4K | 원본 높이 1440 이하에서 높이 2160으로 확대 |
| 원본 FPS | 기존 rVFC 공간 처리. 보간 자원 할당 없음 |
| 48 / 60 / 75 / 90 / 100 / 120 / 144 FPS | WebGPU 움직임 보간의 최대 목표. 실제 제출 FPS는 별도 표시 |
| 채도 / 밝기 | 0–200%, 5% 간격. 100%가 원래 색 |
| 실사 / 애니메이션 | 균형 방식에서 질감 보존 / 윤곽선 재구성 |
| 원본 / 좌우 비교 | 동일한 실제 원본 프레임을 비교하며 보간은 생략 |

목표 해상도는 플레이어 CSS 크기와 분리됩니다. GPU 성능·메모리 한도 때문에 실제 처리 크기가 낮아지면 이유를 표시합니다. 조건에 맞지 않는 원본을 조용히 축소하지 않습니다. 예를 들어 **1920×960 영상은 1440p를 선택**해야 확대 조건에 맞습니다. 1080p 선택에서는 원본 크기를 유지합니다.

Fast는 가벼운 경계선 보간입니다. Balanced는 FSR1 EASU 기반 12탭 재구성, 실사/애니메이션 처리, 선택적 노이즈 감소를 제공합니다. 선명도는 이웃 색 범위로 제한됩니다. Anime4K, 신경망 모델, Ultra는 미지원으로 비활성화되어 있습니다.

원본 타임스탬프가 약 24FPS이면 48/60, 약 30FPS이면 60/90, 약 60FPS이면 75/100/120/144를 적용합니다. 선택한 값은 저장한 채 정책·화면 갱신률·성능에 따른 실제 적용 상한과 이유를 따로 표시합니다.

## 보간과 성능 보호

원본 rVFC 획득과 출력 rAF를 분리합니다. 연속 원본 프레임을 저해상도로 분석하고, 정방향·역방향 블록 벡터로 중간 시점을 워핑한 다음 공간 재구성과 색상 보정을 수행합니다. CPU 전체 프레임 복사 없이 GPU 텍스처를 재사용합니다. GPU 제출은 최대 3개와 최신 대기 입력 하나로 제한합니다. 원본 스냅샷 3개와 최근 두 프레임 쌍의 움직임 벡터를 재사용하며 오래된 입력은 폐기합니다. 정상 보간 경로는 픽셀 서명 읽기를 기다리지 않습니다.

자동 조절은 움직임 검색 범위·분석 크기를 먼저 낮춘 뒤 필요할 때 공간 처리와 제출 빈도를 줄입니다. 보간이 지속적으로 원본 FPS보다 느리면 10초 동안 원본 FPS의 공간·색상 보정으로 복구합니다. 사용자가 선택한 목표는 바뀌지 않습니다.

보간 제출 시 브라우저 원본 표시 시각 대비 추가 지연을 45ms 이내로 검사합니다. video.currentTime 대비 전체 시간차에는 브라우저의 원본 표시 지연도 포함되며 원본 표시 시계의 허용 오차와 추가 지연 45ms를 합한 상한을 별도로 검사합니다. 이 전체 보호 한도는 원본 주기에 따라 90~135ms입니다. 동작 프레임 유지 시간은 목표 출력 간격과 한 화면 갱신 간격을 허용하며, 정지/원본 대체 출력에는 원본 한 간격도 허용하므로 실제 표시까지 45ms 상한을 보장하지 않습니다. 오래되거나 동기화가 끊긴 결과는 숨깁니다. 오디오에 지연을 추가하지 않으므로 완전한 음성 동기화를 보장하지 않습니다. 동기화 가능한 구간이 없으면 결과를 폐기하고 원본 재생으로 복귀합니다. 1배속 15 FPS처럼 한 프레임이 45ms를 초과하면 보간을 생략합니다.

팝업의 Canvas 제출 FPS, 중간 프레임 제출 FPS, 최근 2초의 고유 픽셀 표본 수, 브라우저 갱신률 추정은 서로 다른 값입니다. 고유 표본은 선택적 진단 모드에서만 읽는 256픽셀 GPU 서명이며 전체 픽셀 고유성 증명이 아닙니다. 일반 모드에서는 표본 읽기를 생략합니다. **물리 모니터 표시 FPS는 측정하지 않습니다.** 120 FPS를 선택해도 120개 고유 화면 표시를 보장하지 않습니다.

## 개발과 검증

Node.js 22.12 이상 또는 24 LTS를 사용합니다.

~~~sh
npm install
npm run build
npm run test
npx playwright install chromium
npm run test:browser
~~~

브라우저 검사는 최신 dist를 필요로 합니다. npm run dev 후 http://127.0.0.1:5173/harness/ 에서 진단 화면을 열 수 있습니다. 배포본에서도 chrome-extension://확장프로그램ID/harness/index.html 로 실행됩니다. 포함된 합성 WebM과 GPU 픽셀 검증은 진단용임을 명시합니다. 개인 파일은 객체 URL로 로컬 재생하며 업로드하지 않습니다.

추가 실행 도구:

~~~sh
node scripts/stability-v121.mjs after matrix
node scripts/stability-v121.mjs after long
node scripts/stability-v121.mjs after combinations
node scripts/ablation-v121.mjs
node scripts/verify-stability-youtube.mjs
# 과거 v1.2 재측정 도구 (과거 문서 경로에 기록)
node scripts/benchmark-v12.mjs
node scripts/verify-v12-youtube.mjs
node scripts/verify-youtube.mjs docs/v1.2
node scripts/verify-browsers.mjs docs/v1.2
~~~

핵심 코드: src/content/VideoProcessor.ts, src/temporal/, src/gpu/MotionEstimator.ts, src/shaders/motion-*.wgsl, src/adaptive/, src/settings/, src/popup/. 별도 content IIFE와 서비스 워커를 번들링하며 배포본은 개발 서버·node_modules·원격 코드에 의존하지 않습니다.

## 제한과 보안

CORS·DRM·origin-clean 정책을 우회하지 않습니다. 접근할 수 없는 영상은 정확한 오류 상태와 원본 재생을 유지합니다. WebGL2에서는 공간·색상 처리만 지원합니다. 숨겨진 탭, 탐색, 해상도 변경, GPU 손실에서 오래된 출력을 숨기고 자원을 정리합니다. 기존 유튜브 SPA 탐색과 플레이어 컨트롤을 유지합니다.

빠른 이동, 회전, 가려짐, 복잡한 자막은 블록 보간의 한계입니다. 저신뢰 영역은 보수적으로 한 방향 워핑 또는 원본을 사용하지만 왜곡 제거를 보장하지 않습니다. 장면 전환 검출은 휴리스틱입니다. 전용 코덱 블록 제거, 신경망 디테일 복원, HDR 색 관리, GPU 하드웨어 사용률·전력 측정은 구현하지 않았습니다. SDR 영상으로 사용하세요.
